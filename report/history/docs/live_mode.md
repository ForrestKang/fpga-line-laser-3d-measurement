# 实时模式：相机直通 PFO3

**目标**：PL 按相机帧率处理每一帧，ARM 退出逐帧循环。HDMI 上的点云、截面寄存器、PL 测量都跟着相机实时更新。

## 为什么要改

旧数据路径，每帧都由 ARM 驱动：

1. ARM 请求采集，原图写入 DDR（约 57 ms）；
2. ARM 启动 DMA，把原图送进 PFO3，结果写回 DDR（约 55 ms，PL 计算本身约 4.5 ms）；
3. ARM 用 Python 解包、画页（每帧约 200 ms）。

结果是约 3 帧/秒。相机实测帧周期 18.5 ms，即约 54 帧/秒。

### 寄存器（PFO3 窗口）

| 偏移 | 内容 |
| --- | --- |
| 0x024 | 写：b0 实时开关，b1 转出下一包，b2 复制下一帧原图。读：{b4 本包复制, b3 本包实时, b2 复制待定, b1 转出待定, b0 开关} |
| 0x028 | 实时包计数 |
| 0x02C | 带错误尾的实时包计数 |
| 0x030 | 最近一次转出包的序号 |
| 0x034 | 最近一次复制原图的包序号 |

### 行为

- **回放模式（开关 = 0，默认）**：相机流原样直通原图 DMA。ARM 寄存器启动和 DMA 输入保持原样；集成用例结果必须与原来逐字节一致。
- **实时模式（开关 = 1）**：
  - 上一包输出结束后，自动开始下一包（头部取当前配置字）。
  - 本包输入未满且相机核 ready 时，发出采集请求，冷却 16 拍。
  - 输入来自相机流。输出包默认在 PL 内吃掉；点云视图、PL 测量、截面测量照常从几何记录取数，并按包提交。
  - 置 b1 时，下一包输出走 DMA；置 b2 时，下一帧原图同时复制到原图 DMA。
- **不做 abort**：abort 会清掉几何系数。帧被截断时，下一帧在错误的字节数处触发前端帧错误，包以错误尾结束，消费者丢弃，下一包继续。
- **实时开启期间**允许改写头部配置字（ARM 写入身份与电机步数，下一包生效）。

  - 预热包之后切到实时；

## 板上实测（2026-10-28 板钟，boot 98c97835）

- 固件 `board/deploy_live`（bit `342c43fa…`，WNS +0.068 ns，LUT 73.1%，BRAM 78.9%）。只在本次开机加载，`/boot` 未改。
- 回放模式（旧数据路径）在新 bit 上正常：2.9 帧/秒，无错误。
- 相机直通 60 秒，不动电机：
  - PL 处理 1630 包，0 错误包，**27.4 帧/秒**；
  - ARM 取样和页面刷新 2.9 帧/秒（取一包约 74 ms，解码和画页约 100 ms）。
- 第一次试跑发现取包缺陷：
  - 原图 DMA 借用缓冲后未归还，第二次取包失败；
  - 失败时 PFO3 接收描述符已挂上却没有转出包，DMA 停不下来，后续启动被拒。
- 修正（`transport.py`）：
  - 先挂原图 DMA，再挂 PFO3 接收；
  - 每次取包后归还缓冲（只动自己的缓冲）；
  - 已请求转出时等它落地；没有请求时只复位 PFO3 DMA。
  - 离线测试见 `r33/tests_live_grab.py`（5 项）。

### 为什么是 27 帧而不是 54 帧

每包输入满、计算约 4.5 ms、输出结束后才开始下一包并请求采集。请求到达时，相机下一帧已经开始，采集核要等再下一帧，所以每两帧处理一帧。要到 54 帧，需要在上一包计算期间就预约下一帧，并让 PFO3 在计算时接收下一帧输入，要改 RTL 并重新实现。

### 预约下一帧（54 帧方案，待上板）

仿真实测：一帧最后一个像素进入后，PFO3 约 147k 周期（100 MHz 下 1.47 ms）才发出下一次采集请求，长于相机帧间隔，所以隔帧处理。

`r35_axi.sv` 改为本帧输入收满且采集核空闲时立即预约下一帧：

- 预约的帧在 P2 原图 FIFO（16 KB，约 0.77 ms）里等本包算完。帧间消隐不少于约 0.7 ms 时不会溢出。
- 若预约的帧出错（例如 FIFO 溢出），本次实时会话停止预约，退回 27 帧。重新打开实时模式后再试。
- ARM 在已有预约时请求转出或复制，PL 跳过这一帧，改用其后的一帧，保证所用帧在请求之后才开始采集。
- 关闭实时模式时，如果还有预约帧，PL 收下它并丢弃，不送进原图 DMA。
- `0x024` 读出新增两位：b5 `early_ok`（预约开启），b6 `booked`（已有预约）。

仿真结果（`LIVE_N=3`，T05）：

- 请求在本帧最后一个字后 22 个周期发出；
- 预约帧在 FIFO 等待 147k 周期，与原来的尾部时间一致；
- 复制请求落在跳过预约帧后的下一包；
- 关闭时预约帧被丢弃，无多余包、无原图输出。

#### 上板结果（boot 6bbb154e，bit f1b506d4…）：撤回

- 相机实测 54 帧/s：像素时钟 24 MHz，帧周期 18.5 ms，消隐约 1.6 ms。
- 预约生效，但板上从本帧输入收满到下一包开始约 4.9 ms（仿真 1.47 ms）。预约帧在 P2 FIFO 溢出后被 P2 丢弃，PL 仍为 27.4 帧/s。
- 溢出偶尔发生在 PFO3 已开始接收之后，留下半帧，产生错误包（约 172 万包中 2 个）。
- section 只发布无错误的包，运行时却按 PFO3 序号计算目标，所以每个错误包都会让这一轮报 `section packet identity advanced unexpectedly` 而失败。
- 处理：
  - `r35_axi.sv` 恢复为预约前的版本，保留 section 的 se_u 时序修正，另行重建；
  - 预约版本存于 `archive/pre_merge_20261030/r35_axi_booking.sv`；
  - `live.py: section_target` 扣除 live_start 以来的错误包数。

### 扫描提速（运行时）

每个视角原来约 1.07 s：电机移动约 0.16 s（含使能/方向建立 100 ms、16 个脉冲 60 ms），之后要等 3 个 ARM 处理过的帧（每帧约 0.34 s）。

- 实时模式下，静置帧改为数 PL 包（`live.py: settle_on_pl`）：
  - 移动结束后再完成 2 个包，并满足 `settle_s`（0.1 s），才取被接受的帧；
  - 静置帧不解码。
- 电机（`scan_live.py`）：
  - 由 5 RPM 提高到 20 RPM（周期 93 750 周期，16 个脉冲 15 ms）；
  - 使能/方向建立时间由 100 ms 降到 20 ms。
- 预计每视角约 0.5 s。重试视角多 1–2 帧。

### PL 点云视图按转台角度成形（运行时）

- PL 几何记录同时给出相机坐标和转台轴坐标。几何参数里的角度只转动轴坐标的方位角：
  - 相机坐标、轴半径、轴向高度都不变（用标定数据对三个像素点验证过）；
  - section 只用相机坐标，测量只用半径和高度，都不受影响；
  - 只有点云视图使用轴坐标的 x/y。
- `live.py: ViewScanSync`：
  - 扫描开始时清空视图；电机移动时停止插入；
  - 每次移动后暂停实时流，写入新角度（电机步数，精确值），再恢复实时流并开始插入；
  - 扫描结束后停止插入，完整点云一直显示到下一次扫描。
- `transport.live_reangle`：
  - 先写 `0x024=0`，等当前包结束，再配置几何参数，最后写 `0x024=1`；
  - 有未完成的转出或复制时拒绝执行。
- 视图网格改为实物尺度（`--pl-view-voxel-mm 3`，`--pl-view-z0-mm -150`）：
  - 半径 96 mm；
  - 轴向从 -150 mm 到 +106 mm（ingest 的 24 位差值限制在 256 mm 以内）；
  - 背景落在网格外，自动裁掉。
- 转轴标定之前，轴仍是临时估计，物体会拖成螺旋；标定之后同一路径直接成形。
