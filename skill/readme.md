# 可复用的 PYNQ Overlay 校验技能

从工程复制和部署中常见的文件遗漏、软件与固件混用问题，提炼出两个只读校验脚本。工具不依赖线激光算法、PYNQ-Z2、固定寄存器地址或本仓库目录；其他图像、采集和控制工程可使用自己的清单直接调用。

## 适用范围与输入输出

| 工具 | 适用场景 | 输入 | 输出 |
|---|---|---|---|
| `pynq_release_check.py` | Overlay 与主机驱动配套交付 | 固件清单、运行程序根目录 | 文件与程序绑定结果、逐项错误、退出码 |
| `verify_bundle.py` | 工程包复制与归档后核对 | 工程根目录及 `manifest_sha256.json` | 缺失、损坏、额外文件与路径检查结果 |

只需 Python 3.10 或以上与标准库，不需要安装 PYNQ、Vivado，也不需要连接板卡。复制整个 `skill/` 目录即可在其他工程中使用。

需要Agent自动识别时，在仓库根目录生成安装包（输出目录须已存在，ZIP不得覆盖已有文件）：

```powershell
New-Item -ItemType Directory -Force D:/skill_packages | Out-Null
python -B sim/tools/build_skill.py --output D:/skill_packages/pynq_overlay_skill.zip
```

解压后，将`pynq-overlay-check`整个目录放入目标工程的`.agents/skills/`，再重新加载目标工程的技能列表。不要只复制入口文件，脚本和说明必须随目录一起保留。`validation/`是测试记录，留在安装目录外即可。

仓库的`skill.md`在打包时转换为标准`SKILL.md`，保持提交源码文件名小写。导出采用固定文件清单，包含两个检查器、说明和独立自测，不带本项目固件、标定、运行数据或凭据；相同源码和Python/zlib环境重复打包，ZIP逐字节一致。导出回归在仓库根目录运行`python -B sim/tools/test_build_skill.py`，验证包内工具脱离源码目录仍可运行。

## 使用方法

进入复制后的技能目录，路径换成自己的工程：

```powershell
python -B pynq_release_check.py --manifest ../filter_overlay/manifest.json --runtime-root ../filter_runtime
python -B verify_bundle.py ../filter_project
```

Overlay 清单的字段、完整示例与退出码见[接口说明](pynq_release_check.md)。整包清单使用 `files` 数组，每项包含相对路径 `path`、字节数 `size` 和 `sha256`；文件名遵循小写英文、数字、下划线或连字符的提交约定。

输入清单应由可信的构建记录冻结。发现不一致时检查文件来源并恢复正确配套，不能直接重算错误文件的摘要，把失败变成通过。

## 独立复用测试

```powershell
python -B test_pynq_release_check.py
python -B test_verify_bundle.py
python -B test_portability.py
```

`test_portability.py` 在临时目录建立图像滤波和信号采集两个独立的合成工程，使用不同的文件名和驱动目录。它检查正常配套、交叉混用驱动、目录迁移、脱离本仓库的独立调用，以及检查前后输入内容不变。测试中的板卡名称用于排除型号硬编码，bit/HWH 为测试字节，不是可加载固件。

工具回归另覆盖损坏或缺失清单、重复JSON键、非法字段、中文与空格路径、UTF-8 BOM、旧编码控制台、报告防覆盖、链接和分块读取；结果见工程的`sim/results/skill_regression.json`。符号链接用例依运行环境记录跳过原因。

`test_pynq_release_check.py` 和 `test_portability.py` 使用 `--report <新文件.json>` 保存测试报告；检查器 `pynq_release_check.py` 使用 `--output <新文件.json>` 保存检查结果，两者不能混用。已有报告不会被覆盖。复用测试结果保存在工程的 `sim/results/skill_portability.json`，本目录移到其他工程后可直接重新运行。

## 从开发失败中提炼的规则

| 观察到的问题 | 可复用的处理方式 |
|---|---|
| bit/HWH 没变，但两个驱动文件已更新，原清单仍引用旧代码 | 同时冻结固件文件与关键驱动，分别报告不一致项 |
| 归档只有 JSON 回执，原图、观测和点云没有复制完整 | 整目录复制、逐文件核对并按格式读回，完成后再回收原副本 |
| 日志与 payload 的空文件含义不同 | 按格式合同判断；预期非空的数据文件不能以“文件存在”算成功 |

## 失效条件

- 不可信的清单不能确认发布者身份；文件摘要不等同于数字签名。
- 校验结束后文件仍可被外部修改，部署时应使用冻结目录。
- 文件配套通过不代表器件兼容、硬件已加载或算法精度通过。运行验证由各工程完成，脚本不加载固件、不访问寄存器。

本技能可用于工程交接与竞赛复用；装置专用的开发调试规则留在目标工程内。

## 通用术语与参数

| 术语 | 含义 | 由使用者提供 |
|---|---|---|
| 目标平台 | 开发板、器件和运行环境 | 实际型号与工具版本；文件校验任务可不需要 |
| 硬件产物 | 构建得到的逻辑文件及接口描述 | 文件位置与可信构建来源；角色名自定，常见为bit/HWH |
| 主机程序 | 调用硬件的驱动、库和业务程序 | 运行程序根目录与需要绑定的文件 |
| 接口合同 | 双方约定的数据结构与行为 | 字段、类型、单位、顺序、错误状态和版本 |
| 黄金参考 | 用于确认结果的独立参考实现或冻结数据 | 来源、输入对应关系和比较规则 |
| 正确性 | 输出是否符合合同 | 哪些字段逐位一致、哪些允许误差及具体容限 |
| 性能 | 完成指定工作量的速度和成本 | 计时边界、输入规模、吞吐、延迟、CPU或资源指标 |
| 完成条件 | 可以交付的可观察结果 | 必需输出、通过标准和故障处理方式 |

不预设板型、图像尺寸、算法、时钟、寄存器地址、路径或数值容限。仅请求文件检查时，不要求补齐无关硬件参数；需要某项但没有来源时，先标明缺失，不能按旧项目猜。

## 按任务选用流程

先读取用户指定的目标与合同，再选一个流程。发现多个工程、清单或配置时，用构建关系和用户指定的对象确认，不能直接取搜索到的第一个文件。已经明确的授权继续沿用；检查文件不会自动变成加载或运行硬件。

| 任务 | 最少输入 | 执行方式 | 本包验证范围 |
|---|---|---|---|
| 文件配套 | 清单、运行程序目录 | 调用本目录检查器；输出具体错误与退出码 | 两个独立合成工程及故障用例已验证 |
| DMA诊断 | 接口合同、HWH或对应BD、实际驱动版本、日志 | 先分析模式、通道和缓冲生命周期，再按授权运行目标工程测试 | 提供流程；没有统一DMA执行器 |
| 黄金参考比对 | 同一输入的参考与候选结果、字段和误差合同 | 复用目标工程比较器；核对身份、形状、顺序、单位及差异 | 提供流程；由各工程测试证明结果 |
| 性能与资源分析 | 同口径时间线、构建报告和配置 | 区分调度等待与计算、活动期与收尾、综合与布线后结果 | 提供流程；不推算未做的板测 |

文件配套只需要前两项文件输入，不要求器件型号、地址或PYNQ环境。其他流程只加载它实际需要的资料，不预装整套EDA工具，也不为缺少可选插件阻断已有的离线分析。

### 文件配套提示词

```text
检查 [清单路径] 与 [运行程序根目录] 是否配套。
允许只读，报告保存到 [新输出位置]。使用此技能的校验脚本，
返回通过/失败、退出码及具体不一致项。不要重写输入清单，
不要加载Overlay。缺少输入时指出缺少哪一项，先完成已有文件检查。
```

### DMA诊断提示词

```text
分析 [目标工程] 的DMA问题，输入为 [接口合同、HWH/BD、日志]，
实际运行环境为 [已知版本；未知则先从现有资料识别]。
先确认simple/SG模式、实际驱动支持、MM2S/S2MM通道、传输长度、
对齐/DRE、流数据宽度、TKEEP/TLAST和完成状态，不套用固定IP名或地址。
整理缓冲的申请、CPU写入、设备读取/写入、CPU读取和释放顺序；
按实际coherent属性和驱动实现判断flush/invalidate，避免遗漏或重复同步。
设备尚未完成访问前不得释放或复用缓冲，视图仍在使用时不得覆盖底层数据。
当前允许动作是 [只读 / Mock / 已授权设备测试]，超时使用目标工程的
停止恢复合同；不能假定所有驱动都有wait(timeout=...)，也不盲目复位DMA。
区分等待未完成、人工中止、驱动超时异常和硬件错误状态；没有错误码或
限时记录时，描述为等待未完成，不把它直接认定为驱动或硬件超时。
只读或Mock结果分别报告，不写成真实吞吐、真实传输或缓存一致性已通过。
```

### 黄金参考比对提示词

```text
将 [候选结果] 与 [参考结果] 按 [比较合同] 对照，输入身份必须匹配。
合同明确字段、类型、单位、顺序、定点舍入，以及逐位一致或允许误差。
先检查缺失/重复记录、长度、形状、NaN/Inf和标识，再比较数值。
仅在合同允许时按身份排序；不要通过改变顺序或放宽容限隐藏差异。
输出差异总数、最大误差、首个差异位置及输入来源。
允许修复时完成修改和相同样本回归；失败输入及原结果保留。
```

### 性能与资源分析提示词

```text
按 [相同输入、配置及计时边界] 比较基线与候选。
报告读取和运行测试分别进行；仅在需要且工具实际可用时调用EDA。
分别给出计算、等待、搬运、绘制、持久化和结束阶段，
并行重叠区间不能直接相加，入队时间不能当作持久化完成时间。
从实际报告读取目标器件、时钟、综合/布线阶段、LUT/FF/BRAM/DSP、
WNS/WHS/TNS及适用的CDC结果；没有的指标标为缺少，不能补成0。
给出修改前后同口径收益与代价。仅完成OOC、仿真或PC测试时，
结果就保持该范围，不外推为整板或实物结果。
```

## 通用任务合同

```text
任务类型：[文件配套检查 / DMA诊断 / 黄金参考对照 / 性能与资源分析]
目标工程：[工程根目录或独立技能目录]
输入及来源：[文件路径、清单、参考数据、工具报告；按任务提供]
接口与比较合同：[字段、类型、单位、精度、顺序；文件检查可不填]
输出位置：[本次输出目录]
允许的动作：[只读 / 新建测试副本 / 修改指定文件 / 另有明确授权的操作]
验收标准：[必须通过的检查、允许差异及失败时保留的内容]

先检查现有输入，识别需要的合同和实际依赖，不套用其他工程的板型、
地址、阈值或时钟。只读取与本任务相关的材料，不加载整套知识库。
文件配套检查调用本目录脚本；其他任务使用目标工程已有的参考和工具。
不能用文件匹配代替功能验证，也不能靠改清单或比较规则消除失败。
有差异就定位到具体文件、字段或阶段；允许修改时完成修改、回归与验证。
能够继续的工作持续推进，只有缺少必要外部输入或超出授权才停在对应步骤。
交付输入来源、实际命令、结果和未完成项；现有证据不足时不编造结论。
```

上述模板用于组织任务，不额外授予固件加载、寄存器写入或运动权限。文件检查场景已用独立合成工程核对；其余模板须结合各工程验证，不将提示词审查当作硬件测试。
