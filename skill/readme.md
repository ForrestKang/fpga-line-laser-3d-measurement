# 通用PYNQ工程诊断技能

本技能把开发中的DMA等待、缓冲复用、参考结果错配和计时误判整理为可复用工作流。换题目或换板卡时，由使用者提供实际接口与测试资料，不绑定某个算法或固定平台。

## 三项流程

| 流程 | 适用场景和最少输入 | 使用方法与输出 | 失效条件 |
|---|---|---|---|
| DMA与缓存诊断 | 传输不结束、旧数据、偶发错帧；需要HWH/BD、实际驱动和日志 | 按模式、长度、结束信号和缓冲所有权顺序定位，给出证据及检查动作 | 只有一条“卡住”描述时不能唯一判断原因；资料分析不能代替设备测试 |
| 黄金参考比对 | 软件、RTL或板端结果对照；需要同一输入、两份结果及字段/单位/顺序/容限合同 | 先核对身份和结构，再比较逐字段数值，报告缺失、重复与首个差异 | 参考和候选输入不对应，或误差合同缺失时，不能作精度结论 |
| 性能与资源分析 | 优化前后对照；需要配置、时间线、器件与工具报告 | 拆分计算和等待，处理重叠区间，关联真实资源及时序代价 | 不同输入或计时边界不可直接比较；模块OOC结果不能当整板结果 |

## 调用方式

将本目录的`skill.md`作为智能体入口，说明当前任务和资料位置。可直接使用下面的模板：

```text
使用PYNQ工程诊断工作流处理以下问题。
任务：[DMA与缓存 / 黄金参考比对 / 性能与资源]
资料：[实际工程、接口、驱动、日志、参考结果或工具报告的位置]
比较合同：[帧身份、字段、形状、单位、顺序、舍入和允许误差；按任务填写]
允许动作：[只读分析 / 在新副本修改与测试 / 已明确授权的设备操作]
目标：[希望解决的问题和可观察的完成条件]
输出：[本次工作目录]

先依据实际资料确认事实，再定位与修复；原数据和失败结果保留。
缺少证据时指出具体缺项，继续完成不依赖该缺项的工作。
```

## 提炼来源

- 等待在人工停止后结束，曾被误写成“DMA超时”：现在先找超时期限、异常与状态证据。
- 已返回的数组仍指向下一帧会复用的缓冲：现在按设备和消费者生命周期核对所有权，而不只看对象名称。
- measurement与preview接受集合不同，直接共享整份结果会混入暂定点：现在先确定比较身份和独立掩码。
- CPU计算与DMA等待部分重叠，简单相加无法解释整链节拍：现在按时间线区分阶段成本与关键路径。
- 模块综合通过但整板未完成布线：现在对报告阶段分别陈述结论。

这些规则来自实际开发观察；用于新工程时仍要以新工程的数据、驱动和测试验证。

## 验证范围

随仓库的`sim/tools/test_build_skill.py`验证导出内容完整、重复导出一致、原文件不变、旧输出不覆盖、缺少输入拒绝，以及中文和空格目录中解压后的入口和相对引用可独立读取。它检验技能交付方式，不把文档可读性当作DMA、精度或吞吐已通过。

另完成三个独立案例试用：区分人工中断与DMA超时、区分模块OOC与整板实现、按合同拒绝点记录错序。三例结论与给定日志和比较合同一致；没有在线板卡时，结果保持为资料分析，不作为设备性能或测量精度验证。

## 独立安装

在工程根目录执行，输出路径使用新文件且放在工程外：

```powershell
python -B sim/tools/build_skill.py --output ../pynq_engineering_workflow.zip
python -B sim/tools/test_build_skill.py
```

导出包只有`pynq-engineering-workflow/SKILL.md`和`readme.md`。把`pynq-engineering-workflow`放入其他工程的`.agents/skills/`并重新加载技能列表即可。提交源码文件名保持小写，导出时生成平台识别所需的`SKILL.md`。
