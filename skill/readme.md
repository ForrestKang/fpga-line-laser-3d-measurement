# 可复用的 PYNQ Overlay 校验技能

从工程复制和部署中常见的文件遗漏、软件与固件混用问题，提炼出两个只读校验脚本。工具不依赖线激光算法、PYNQ-Z2、固定寄存器地址或本仓库目录；其他图像、采集和控制工程可使用自己的清单直接调用。

## 适用范围与输入输出

| 工具 | 适用场景 | 输入 | 输出 |
|---|---|---|---|
| `pynq_release_check.py` | Overlay 与主机驱动配套交付 | 固件清单、运行程序根目录 | 文件与程序绑定结果、逐项错误、退出码 |
| `verify_bundle.py` | 工程包复制与归档后核对 | 工程根目录及 `manifest_sha256.json` | 缺失、损坏、额外文件与路径检查结果 |

只需 Python 3.10 或以上与标准库，不需要安装 PYNQ、Vivado，也不需要连接板卡。复制整个 `skill/` 目录即可在其他工程中使用。

## 使用方法

进入复制后的技能目录，路径换成自己的工程：

```powershell
python -B pynq_release_check.py --manifest ../filter_overlay/manifest.json --runtime-root ../filter_runtime
python -B verify_bundle.py ../filter_project
```

Overlay 清单的字段、完整示例与退出码见[接口说明](pynq_release_check.md)。整包清单使用 `files` 数组，每项包含相对路径 `path`、字节数 `size` 和 `sha256`；文件名遵循小写英文、数字、下划线或连字符的提交约定。

输入清单应由可信的构建记录冻结。发现不一致时检查文件来源并恢复正确配套，不能直接重算错误文件的摘要，把失败变成通过。

## 独立复用测试

```powershell
python -B test_pynq_release_check.py
python -B test_verify_bundle.py
python -B test_portability.py
```

`test_portability.py` 在临时目录建立图像滤波和信号采集两个独立的合成工程，使用不同的文件名和驱动目录。它检查正常配套、交叉混用驱动、目录迁移、脱离本仓库的独立调用，以及检查前后输入内容不变。测试中的板卡名称用于排除型号硬编码，bit/HWH 为测试字节，不是可加载固件。

Overlay 与复用测试支持 `--report <新文件.json>` 保存结构化结果；已有报告不会被覆盖。复用测试结果保存在工程的 `sim/results/skill_portability.json`，本目录移到其他工程后可直接重新运行。

## 从开发失败中提炼的规则

| 观察到的问题 | 可复用的处理方式 |
|---|---|
| bit/HWH 没变，但两个驱动文件已更新，原清单仍引用旧代码 | 同时冻结固件文件与关键驱动，分别报告不一致项 |
| 归档只有 JSON 回执，原图、观测和点云没有复制完整 | 整目录复制、逐文件核对并按格式读回，完成后再回收原副本 |
| 日志与 payload 的空文件含义不同 | 按格式合同判断；预期非空的数据文件不能以“文件存在”算成功 |

## 失效条件

- 不可信的清单不能确认发布者身份；文件摘要不等同于数字签名。
- 校验结束后文件仍可被外部修改，部署时应使用冻结目录。
- 文件配套通过不代表器件兼容、硬件已加载或算法精度通过。运行验证由各工程完成，脚本不加载固件、不访问寄存器。

本技能用于自主选题赛道的工程复用；本地开发调试技能用于装置的工程适配。

## 通用术语与参数

| 术语 | 含义 | 由使用者提供 |
|---|---|---|
| 目标平台 | 开发板、器件和运行环境 | 实际型号与工具版本；文件校验任务可不需要 |
| 硬件产物 | 构建得到的逻辑文件及接口描述 | 文件位置与可信构建来源；本校验器采用bit/HWH清单 |
| 主机程序 | 调用硬件的驱动、库和业务程序 | 运行程序根目录与需要绑定的文件 |
| 接口合同 | 双方约定的数据结构与行为 | 字段、类型、单位、顺序、错误状态和版本 |
| 黄金参考 | 用于确认结果的独立参考实现或冻结数据 | 来源、输入对应关系和比较规则 |
| 正确性 | 输出是否符合合同 | 哪些字段逐位一致、哪些允许误差及具体容限 |
| 性能 | 完成指定工作量的速度和成本 | 计时边界、输入规模、吞吐、延迟、CPU或资源指标 |
| 完成条件 | 可以交付的可观察结果 | 必需输出、通过标准和故障处理方式 |

不预设板型、图像尺寸、算法、时钟、寄存器地址、路径或数值容限。仅请求文件检查时，不要求补齐无关硬件参数；需要某项但没有来源时，先标明缺失，不能按旧项目猜。

## 可直接填写的提示词

```text
任务类型：[文件配套检查 / 黄金参考对照 / 性能与资源分析]
目标工程：[工程根目录或独立技能目录]
输入及来源：[文件路径、清单、参考数据、工具报告；按任务提供]
接口与比较合同：[字段、类型、单位、精度、顺序；文件检查可不填]
输出位置：[本次输出目录]
允许的动作：[只读 / 新建测试副本 / 修改指定文件 / 另有明确授权的操作]
验收标准：[必须通过的检查、允许差异及失败时保留的内容]

先检查现有输入，识别需要的合同和实际依赖，不套用其他工程的板型、
地址、阈值或时钟。只读取与本任务相关的材料，不加载整套知识库。
文件配套检查调用本目录脚本；其他任务使用目标工程已有的参考和工具。
不能用文件匹配代替功能验证，也不能靠改清单或比较规则消除失败。
有差异就定位到具体文件、字段或阶段；允许修改时完成修改、回归与验证。
能够继续的工作持续推进，只有缺少必要外部输入或超出授权才停在对应步骤。
交付输入来源、实际命令、结果和未完成项；现有证据不足时不编造结论。
```

上述模板用于组织任务，不额外授予固件加载、寄存器写入或运动权限。其可用性通过独立合成工程的文件检查场景核对；黄金参考和性能分析仍须运行各工程自己的测试。
